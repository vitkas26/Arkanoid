# Arkanoid Christmas — план работ

Статус: задачи реализованы в ветке `feature/arkanoid-modernization`. Каждый тикет закрыт отдельным коммитом. Приёмка: `assembleDebug` и 12 JVM-тестов прошли; 4 Android-теста прошли на Pixel 4 (Android 10) в эмуляторе 28.09.2026.

## ARK-01 — Обновить сборку Android

**Статус:** готово, коммит `4751698`.

**Проблема.** Gradle, Android Gradle Plugin, Kotlin и target SDK устарели; старую конфигурацию трудно собрать и нельзя использовать для новой публикации в Google Play.

**Решение.** Перейти на совместимые версии Gradle/AGP/Kotlin, `compileSdk` и `targetSdk` 36. Удалить неиспользуемые зависимости. Сохранить существующий `applicationId`.

**Критерии приёмки.** Debug APK собирается; JVM-тесты запускаются; проект не требует ручной правки локального SDK-пути.

## ARK-02 — Вынести правила игры в детерминированный движок

**Статус:** готово, коммит `b888bba`.

**Проблема.** `MainActivity` одновременно хранит правила, координаты Android View, счёт и навигацию; коллизии стен и ракетки повторяются внутри обхода блоков.

**Решение.** Создать независимые от Android `GameEngine` и `GameState` с едиными координатами игрового поля. Один вызов `update(deltaSeconds)` обрабатывает движение и коллизии один раз за шаг. Терминальные состояния `WON`/`LOST` не изменяются после завершения.

**Критерии приёмки.** В движке нет Android API; игра достигает победы/поражения; счёт растёт один раз на разрушенный блок.

## ARK-03 — Тесты правил и регрессий

**Статус:** готово, коммит `ce43efc`.

**Проблема.** Имеющийся тест проверяет `2 + 2`, а физика не проверяется.

**Решение.** Написать JVM-тесты запуска, движения, всех границ, трёх зон ракетки, разрушения блока, счёта, победы и поражения. Проверить инварианты для крупного шага времени.

**Критерии приёмки.** `testDebugUnitTest` проходит; тесты запускаются без эмулятора и воспроизводят сбой при нарушении правил.

## ARK-04 — Перерисовать игровой экран и управление

**Статус:** готово, коммит `70f9d7d`.

**Проблема.** Объекты представлены динамическими `ImageView`, позиции меняются из фонового потока, а зоны касания имеют фиксированные размеры.

**Решение.** Создать `GameView` на Canvas с сохранением пропорций поля и корректным преобразованием касания в координаты игры. Использовать кадровый callback на UI-потоке с расчётом прошедшего времени; останавливать цикл при паузе/уничтожении Activity. Управлять ракеткой перетаскиванием и клавишами.

**Критерии приёмки.** Игра видна полностью на разных соотношениях сторон; касание и клавиши ограничивают ракетку полем; после ухода с экрана кадровый цикл не работает.

## ARK-05 — Экран результата и повтор игры

**Статус:** готово, коммит `32e12f2`. Сам экран результата и обработчик повтора добавлены вместе с новым игровым экраном в ARK-04; этим коммитом удалены неиспользуемые Activity, ресурсы и переходы.

**Проблема.** Результат передаётся строковым ключом между тремя Activity, а повторный старт создаёт новую Activity. Победа/поражение запускаются из игрового цикла.

**Решение.** Показывать результат и кнопку повтора поверх игры в одной Activity. Обновить подписи и доступность управления, сохранить игровое состояние при пересоздании Activity.

**Критерии приёмки.** Победа/поражение и счёт отображаются один раз; повтор создаёт новую игру без стека экранов; вращение/пересоздание не теряет текущий счёт.

## ARK-06 — Инструментальные проверки экрана

**Статус:** готово, коммит `d273972`. Четыре теста прошли на эмуляторе Pixel 4 (Android 10).

**Проблема.** Нет проверки запуска игры, экранов результата и повтора на Android.

**Решение.** Написать Android-тесты на запуск и повтор, проверку границ View и восстановление состояния. Запускать их на доступном эмуляторе или устройстве.

**Критерии приёмки.** `connectedDebugAndroidTest` проходит на устройстве/эмуляторе; результаты записаны в отчёте. Проверены запуск, перетаскивание и клавиатура, победа/поражение с повтором, восстановление после пересоздания Activity и пропорции поля на трёх форматах экрана.

## ARK-07 — Документация и финальная проверка

**Статус:** готово, коммит с README и этим итоговым отчётом.

**Проблема.** В репозитории нет README с управлением, сборкой и архитектурой.

**Решение.** Добавить README, команды сборки и тестов, краткую схему ответственности компонентов. Проверить чистое рабочее дерево и перечислить коммиты.

**Критерии приёмки.** Новый разработчик может собрать и запустить игру по README; все предыдущие критерии проверены, ограничения указаны явно.

## Результат и ограничения

- `:app:assembleDebug` — успешно.
- `:app:testDebugUnitTest` — 12 тестов успешно.
- `:app:connectedDebugAndroidTest` — 4 теста успешно на Pixel 4 (API 29).
- Стартовый экран просмотрен на эмуляторе: поле и игровые изображения видны целиком.
- Проверка на физическом устройстве не выполнялась. Расчёт игрового поля проверен на трёх размерах View; поле масштабируется без изменения пропорций и оставляет свободные полосы на экранах с другим соотношением сторон.
- Минимальная версия Android теперь API 23; устройства на API 19–22 больше не поддерживаются.
- Обновление target SDK до 36 требует проверки поведения на Android 16 перед публикацией; текущий запуск и инструментальные тесты выполнены на Android 10.
